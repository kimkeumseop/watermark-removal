# 클린프레임

영상과 이미지를 서버에 업로드하지 않고 브라우저 안에서 워터마크 영역을 제거하는 정적 웹사이트입니다. 두 가지 도구를 상단 내비게이션으로 오갈 수 있습니다.

- **영상**(`index.html`) — 선택한 고정 영역을 `ffmpeg.wasm`의 `delogo` 필터로 처리하고 MP4로 저장합니다.
- **이미지 일괄**(`image.html`) — 폴더를 불러와 대표 이미지에서 한 번만 위치를 지정하면 폴더 안 모든 이미지의 같은 위치를 처리해 ZIP으로 저장합니다.

## 주요 기능

- 드래그 앤 드롭 또는 파일 선택으로 영상·이미지 폴더 불러오기
- 마우스와 터치로 여러 워터마크 영역 선택
- 선택 영역 개별 삭제와 전체 삭제
- 브라우저 안에서 처리 진행률 확인
- 결과 미리보기와 MP4 다운로드 (영상)
- 전·후 미리보기와 원본 이름을 유지한 ZIP 다운로드 (이미지 일괄)
- 서버 전송 없는 100% 클라이언트 처리

## 로컬 실행

보안 정책상 `index.html`을 `file://`로 직접 열면 Web Worker가 동작하지 않습니다. 프로젝트 폴더에서 로컬 서버를 실행하세요.

```bash
python -m http.server 8000
```

브라우저에서 `http://localhost:8000`을 열면 됩니다. 첫 방문에는 약 31MB인 ffmpeg 코어를 불러오므로 네트워크 환경에 따라 준비 시간이 걸릴 수 있습니다.

## 사용 방법

### 영상

1. 영상을 끌어다 놓거나 파일 선택 버튼으로 불러옵니다.
2. 영상 위에서 지우고 싶은 워터마크 영역을 드래그합니다.
3. 필요한 만큼 영역을 추가하고 잘못 고른 영역은 빨간 × 버튼으로 지웁니다.
4. `워터마크 제거`를 누르고 처리가 끝날 때까지 창을 닫지 않습니다.
5. 결과를 미리 본 뒤 `결과 다운로드`로 MP4 파일을 저장합니다.

200MB가 넘는 파일은 브라우저 메모리 한계 때문에 느려지거나 처리에 실패할 수 있습니다.

### 이미지 일괄

1. 상단 내비게이션에서 `이미지 일괄`을 선택합니다.
2. 폴더를 끌어다 놓거나 클릭해 폴더를 선택합니다. 안에 있는 JPG·PNG·WEBP를 모두 불러옵니다.
3. 대표 이미지(첫 번째 파일)에서 워터마크 영역을 드래그합니다.
4. `전 / 후 미리보기`로 위치가 맞는지 확인합니다.
5. `모두 제거 → ZIP`을 누르면 처리 후 ZIP이 자동으로 저장됩니다.

지정한 영역은 비율로 저장되어 각 이미지 크기에 맞춰 적용됩니다. 모든 이미지가 같은 크기이고 워터마크 위치가 같을 때 가장 정확합니다.

## 배포

별도 빌드 과정이 없는 정적 사이트입니다. `vendor/`를 포함한 프로젝트 폴더 전체를 배포해야 합니다.

### Netlify Drop

1. [Netlify Drop](https://app.netlify.com/drop)에 접속합니다.
2. 프로젝트 폴더 전체를 화면에 끌어다 놓습니다.
3. 포함된 `netlify.toml`과 `_headers`가 wasm MIME과 장기 캐시를 설정합니다.

### Vercel

Vercel CLI를 프로젝트 폴더에서 실행하거나 Git 저장소를 연결합니다.

```bash
vercel
```

포함된 `vercel.json`이 약 31MB인 wasm 파일의 MIME과 1년 장기 캐시를 자동으로 설정합니다.

### GitHub Pages

1. 프로젝트 전체를 GitHub 저장소에 올립니다.
2. 저장소의 Settings → Pages에서 배포 브랜치를 선택합니다.
3. 배포된 Pages 주소로 접속합니다.

`vendor/ffmpeg-core.wasm`이 약 31MB라 저장소 용량이 커집니다. 일반 Git으로 올릴 수 있지만 저장소 정책이나 용량 문제가 있으면 Git LFS 사용을 고려하세요.

## 애드센스 설정

게시자 ID는 `ca-pub-1059415497859090`으로 이미 설정돼 있습니다. 남은 작업은 광고 단위 ID를 넣는 것뿐입니다.

### 게시자 ID가 들어가는 곳

`index.html`, `privacy.html`, `terms.html` 세 파일의 `<head>`에 아래 두 줄이 들어 있습니다.

```html
<meta name="google-adsense-account" content="ca-pub-1059415497859090" />
<script
  async
  src="https://pagead2.googlesyndication.com/pagead/js/adsbygoogle.js?client=ca-pub-1059415497859090"
  crossorigin="anonymous"
></script>
```

애드센스 사이트 확인 크롤러는 HTML 원본에서 이 두 가지를 찾습니다. 스크립트를 JavaScript로 주입하면 크롤러가 못 찾아 "사이트를 확인할 수 없음"이 뜰 수 있으므로, 로더는 반드시 HTML에 그대로 두어야 합니다. `ads.js`는 광고 단위 렌더링만 담당합니다.

### ads.txt

루트의 `ads.txt`에 같은 번호가 들어 있습니다. `ca-` 접두사 없이 적습니다.

```text
google.com, pub-1059415497859090, DIRECT, f08c47fec0942fa0
```

배포 후 `https://도메인/ads.txt`가 열리는지 확인하세요. 이 파일이 없으면 애드센스에 경고가 뜨고 수익이 제한됩니다.

### 남은 작업: 광고 단위 ID 넣기

애드센스에서 **디스플레이 광고** 단위를 만들면 10자리 슬롯 ID가 나옵니다. `index.html`의 광고 자리 두 곳에 각각 넣습니다. 슬롯 ID가 비어 있는 동안에는 `ads.js`가 그 광고 자리를 제거하므로 빈 상자나 콘솔 오류가 보이지 않고, 광고 스크립트 자체는 정상적으로 로드돼 심사에 지장이 없습니다.

```html
<aside class="ad-slot" data-ad-slot="1234567890" data-ad-format="auto" aria-label="광고">
```

광고 자리는 작업 영역 아래와 FAQ 아래에 있습니다. 광고 자리를 늘리려면 같은 형태의 `aside`를 원하는 위치에 추가하면 됩니다. 버튼이나 영상 바로 옆에 붙이면 오클릭 유도로 판단될 수 있으므로 피하세요.

### 사이트 확인이 실패할 때

애드센스에서 "사이트를 확인할 수 없음"이 뜨면 순서대로 확인합니다.

1. 애드센스에 등록한 주소가 실제 배포 주소와 정확히 같은지 확인합니다. `www.` 유무와 도메인 철자가 다르면 실패합니다.
2. 브라우저 시크릿 창에서 배포 주소가 로그인 없이 열리는지 확인합니다. Vercel의 Deployment Protection이 켜져 있으면 구글 크롤러가 접근하지 못합니다. Vercel 프로젝트 Settings → Deployment Protection에서 Production 보호를 꺼야 합니다.
3. 배포본의 HTML 원본(`Ctrl+U`)에 위의 메타 태그와 로더 스크립트가 보이는지 확인합니다.
4. `https://도메인/ads.txt`가 열리는지 확인합니다.
5. 위가 모두 정상이면 애드센스에서 다시 확인을 요청합니다. 반영에 최대 하루 정도 걸리기도 합니다.

### 승인 관련 참고

- 애드센스는 콘텐츠가 얇은 사이트를 반려하는 경우가 많습니다. FAQ 섹션과 약관·개인정보처리방침 페이지를 추가해 둔 이유입니다. 반려되면 사용법·사례 글을 더 채우고 재신청하세요.
- 유럽·영국 방문자가 있으면 애드센스 대시보드의 **개인정보 보호 및 메시지**에서 동의 메시지(CMP)를 켜야 합니다. 코드 수정 없이 대시보드에서 설정합니다.
- 심사 중에도 광고 코드는 그대로 두는 편이 좋습니다. 승인 전에는 빈 영역으로 표시됩니다.

## 동작 방식

### 영상

선택 영역은 표시 화면 좌표에서 영상의 실제 픽셀 좌표로 변환됩니다. 처리할 때 각 영역을 영상 프레임 안쪽으로 제한한 뒤 여러 `delogo` 필터를 연결해 한 번에 적용합니다. ffmpeg 코어와 Worker 파일은 모두 같은 출처의 `vendor/`에서 불러오므로 영상이 외부 서버로 전송되지 않습니다.

단일 스레드 코어를 사용하므로 `SharedArrayBuffer`와 COOP/COEP 헤더는 필요하지 않습니다.

### 이미지 일괄

이미지 모드는 ffmpeg를 쓰지 않습니다. 31MB 코어를 내려받지 않고 바로 처리하려고 `delogo`와 같은 원리를 캔버스에서 구현했습니다. 사각형 내부의 각 픽셀을 좌·우·상·하 테두리 픽셀의 역거리 가중평균으로 다시 채우는 방식입니다.

선택 영역은 대표 이미지 기준의 **비율**로 저장되어, 크기가 다른 이미지에도 같은 비율 위치로 적용됩니다. 각 이미지는 원본 형식으로 다시 인코딩되고, 결과 ZIP은 의존성 없이 `image.js` 안의 `ZipStore`(store 방식, 무압축)로 만듭니다. 이미 압축된 이미지라 추가 압축은 이득이 없기 때문입니다.

## 한계

- 선택한 부분을 주변 픽셀로 보간합니다. 고정 위치의 불투명 사각 로고에서 가장 좋은 결과를 냅니다.
- 반투명 워터마크나 복잡한 배경에서는 흔적이 남을 수 있습니다.
- 움직이는 워터마크는 하나의 고정 영역으로 제거하기 어렵습니다. AI 인페인팅 기능은 이 도구의 범위에 포함되지 않습니다.
- 대용량 또는 고해상도 파일은 브라우저 메모리 한계로 느려지거나 처리에 실패할 수 있습니다.
- 이미지 일괄은 모든 이미지의 워터마크가 같은 비율 위치에 있다고 가정합니다. 위치가 파일마다 다르면 정확도가 떨어집니다.
- 제거 권한이 있는 파일에만 사용해야 합니다.
